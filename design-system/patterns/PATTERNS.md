# Patrones de producto

Los patrones componen componentes para resolver situaciones recurrentes de ARRELS360.

## Planificar y asignar una visita

Contexto y periodo → filtros activos → agenda/tabla → incidencias de cobertura → acción primaria. Un cambio muestra impacto horario y responsable antes de confirmarse.

## Ejecutar una visita

Estado de conexión → visita actual → hora y margen → tareas → acción de fichaje → incidencia. La ubicación se explica como captura puntual y la cola offline permanece visible.

## Construir una ruta

Mapa como apoyo, lista ordenada como fuente operable. Cada parada expone franja, traslado y alertas. Reordenar tiene alternativa por botones/teclado y el sistema no promete optimización automática si no existe.

## Revisar evidencia y preliquidación

Resumen del periodo → excepciones → evidencia → regla aplicada → resultado → decisión. Lo pendiente nunca se confunde con validado ni entra silenciosamente en un cierre.

## Chat con objeto compartido

El chat admite texto y objetos estructurados. Un plan compartido incluye tipo, versión, autor, alcance, resumen y acciones. Aceptar un plan no equivale a ejecutarlo: debe confirmar qué cambiará y generar trazabilidad.

## Incidencia offline

La persona puede guardar tipo, descripción y evidencia sin conexión. Se muestra que queda en el dispositivo, cuándo se reintentará y cómo corregir un fallo de sincronización.

## Seguimiento para familias

Se comunica primero el estado comprensible del servicio; el detalle permitido aparece después. Nunca se muestran datos laborales, clínicos o personales fuera del permiso explícito.

## Acceso familiar y permisos

Invitación → relación → permisos legibles → confirmación → auditoría. Se aplica mínima visibilidad y cada permiso explica qué permite ver o hacer.

## Dashboard de dirección

Periodo y ámbito → métricas verificables → tendencia → excepciones → acceso al detalle. Si un dato no existe o está incompleto, se muestra ausencia/calidad; no se inventa una cifra de relleno.

## Estados transversales

Todo patrón debe prever: carga, vacío inicial, sin resultados, error recuperable, error de permiso, offline, datos obsoletos, acción en curso y éxito.
